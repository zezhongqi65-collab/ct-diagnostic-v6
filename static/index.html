Methodology

三层因果可解释诊断 · 方法说明

本页面说明诊断引擎的结构、因果假设、四分类规则与保真机制，并如实标注网页演示版与科研版（Python / 桌面 exe）的实现差异。

五个计算思维维度与因果 DAG

后门调整沿 DAG 控制父节点混杂：抽象 → 分解、抽象 → 算法设计、算法设计 → 建模、算法设计 → 评估。估计某维度因果效应时，以其父维度作为协变量，剔除上游能力带来的混杂。

维度（全称）量表题项因果父节点（后门调整协变量）
抽象 · 模式识别与抽象A4–A6无（DAG 根节点）
分解 · 问题分解A1–A3抽象
算法设计 · 算法与步骤设计A9–A10抽象
建模 · 数学建模与符号化A7–A8算法设计
评估 · 方案评估与调试A11–A15算法设计

群体因果效应、SHAP 与两条自适应阈值均由后端在参考模型上实时估计，每次诊断随结果返回，前端不写死任何数值。

LAYER 1

反事实分析 CFE

固定其他维度，把单一维度依次设为 1–5，观察模型预测作业质量的变化，给出「若提至满分」增益最大的维度。属模型假设模拟，不等于真实因果。

LAYER 2

SHAP × 因果效应双维度

SHAP 衡量「模型认为该维度对这个学生有多重要」；群体因果效应 × 个体提升空间 headroom=max(0,5−得分) 得到个体化预期收益。两者按自适应阈值划成四象限。

LAYER 3

ITE 个体处理效应

需前后测准实验数据（实验组 / 对照组），用 X-Learner / T-Learner 估计「对这名学生干预是否有效」。本网页版不涉及，科研版 Python 引擎支持。

四分类决策规则（含 headroom 个体化调制）

条件分类含义与动作
|SHAP| 高 且 个体化效应高优先干预立即安排该维度专项训练，给出预计提分
|SHAP| 高 但 个体化效应低仅观察单独干预无效；沿 DAG 追溯薄弱父维度（父维度 <3 分），先练根因
|SHAP| 低 但 个体化效应高潜在有效模型未突出但干预可能有效，作为二级备选
双低，或 headroom < 0.5无需关注接近满分（≥4.5）提升空间不足半格，或当前表现正常
个体化调制用于消除「满分维度仍建议干预」的生态谬误：群体因果效应只代表平均每 1 分的边际作用，乘以该学生的提升空间 headroom 后，才是属于这个个体的预期收益。

保真机制与网页版边界

前后端分工（本页面为纯渲染前端）：前端只负责采集五维 / 量表、调用接口与渲染，不内置任何诊断公式、权重或阈值；作业质量预测、TreeSHAP 归因、后门调整因果效应、自适应阈值与四分类全部由本地 FastAPI 后端（backend.py，XGBoost + TreeSHAP）实时计算并以 JSON 返回。数据仅在本机 127.0.0.1 往返，不上传外网。

三层约束保真：① 报告中所有得分 / SHAP / 因果效应 / 分类 / 建议文字直接取自后端算法输出，前端不改写；② 大模型在科研版中仅做语言润色，不得改动任何数字与分类；③ 自动保真度校验，不通过即回退模板。本前端不接入大模型，展示的是 100% 模板保真结果。

启动后端：在项目目录执行 python -m uvicorn backend:app --host 127.0.0.1 --port 8000，再通过 http://localhost:8000/ 访问本页面（同源调用接口）。正式实验 / 论文请改为在真实前测数据上训练模型（后端 train_on_data）。
